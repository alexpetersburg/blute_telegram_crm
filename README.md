# Blüte — касса в Telegram

Статический клиент в `webapp/` читает прайс из Google Sheets и передаёт заказ существующему aiogram-боту. Структура таблицы (`id`, `name`, `price`, `enabled`, `sort`) и формат заказа `v: 1` сохранены.

Клиент поддерживает поиск по названию и ID (без учёта регистра, е/ё), сортировку, избранное, фильтр состава заказа, редактирование количества и предварительную проверку заказа. Черновик и избранное сохраняются в localStorage на этом устройстве. Если Telegram передаёт ID пользователя, используется отдельный черновик; при запуске через кнопку клавиатуры ID не передаётся и черновик общий для данного хранилища браузера. После отправки черновик остаётся: получение подтверждает бот, для нового заказа используйте «Очистить заказ».

Настройки существующей таблицы находятся в `webapp/config.js`. Клиент только читает таблицу. Недоступные товары и некорректные цены пропускаются. При обновлении прайса удалённые товары исключаются из заказа, цены пересчитываются с уведомлением.

Для публикации загрузите **всю папку `webapp`** на текущий HTTPS-хостинг: `index.html`, `styles.css`, `config.js`, `app.js`. `WEBAPP_URL` бота должен указывать на страницу кассы. Для отправки через `sendData()` открывайте кассу кнопкой «Открыть кассу» из reply-клавиатуры после `/start`, а не кнопкой меню или прямой ссылкой. Обычный браузер поддерживает сбор черновика и просмотр заказа.

Локальный просмотр: запустите статический HTTP-сервер в `webapp`, например `python -m http.server 8080`, затем откройте `http://localhost:8080`.

Проверки интерфейса используют тестовый прайс и имитацию Telegram без реальных отправок. Нужны современный Node.js, Playwright и Microsoft Edge: `node tests/webapp.cjs`. При другом браузере задайте `BROWSER_CHANNEL=chrome`. Можно указать путь к установленному Playwright через `PLAYWRIGHT_MODULE`, а директорию снимков — через `SCREENSHOT_DIR`.
